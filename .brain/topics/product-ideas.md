# Product Ideas

## Context

ชุดไอเดียนี้มาจากการอ่าน brain, DESIGN.md, schema, routes, และรอย TODO ใน repo วันที่ 2026-05-17

โปรเจกต์ตอนนี้มีระบบหลักพร้อมใช้งานหลายส่วนแล้ว จุดที่ควรต่อยอดคือทำให้แอดมินเห็นงานที่ต้องเคลียร์เร็วขึ้น ลดการกรอกซ้ำของพนักงาน และลดความเสี่ยงเรื่องข้อมูลลูกค้า/บิล/สลิป/มิเตอร์

## Recommended Ideas

### Daily action center

ทำหน้าเดียวสำหรับแอดมินที่รวมงานค้างของวันนี้ เช่น กะยังไม่ปิด สลิปโอนยังไม่มี รูปมิเตอร์ไม่ครบ เงินเชื่อขาดลูกค้า/ทะเบียน/เลขบิล ถังแก๊สต่ำ และใบวางบิลเกินกำหนด

ฐานข้อมูลและ API ปัจจุบันมี alerts หลายจุดอยู่แล้ว จึงเหมาะกับการรวมเป็นหน้าจัดการงานประจำวันมากกว่าสร้างระบบใหม่ทั้งหมด

### Real tank stock for SIMPLE stations

เปลี่ยน `/api/v2/simple/admin/stock` จาก mock เป็นข้อมูลจริง โดยเพิ่มข้อมูลถัง น้ำมันรับเข้า ยอดขายเฉลี่ย และวันที่ควรสั่งน้ำมัน

จุดนี้มีผลกับงานจริงสูง เพราะ route ปัจจุบันระบุไว้ชัดว่าเป็น mock และยัง random ปริมาณคงเหลืออยู่

### LINE payment flow upgrade

ต่อยอด LINE webhook ที่มีแล้วให้ลูกค้าดูยอดค้าง ส่งสลิป และแนบเลขใบวางบิลได้ง่ายขึ้น

ควรเพิ่มหน้าผูก LINE user กับ owner, ตรวจยอดสลิปจากจำนวนเงิน, และแจ้งแอดมินเมื่อมีสลิปรอตรวจ

### Owner cleanup and merge assistant

ทำหน้าแอดมินสำหรับรวมลูกค้าซ้ำ, เติม ownerId ให้ transaction เก่า, และเตือนชื่อหรือ code ที่ซ้ำก่อนสร้างลูกค้าใหม่

งานนี้ลดความเสี่ยงใบวางบิลผิดคน เพราะ brain เคยบันทึกว่า owner name และ code มีรายการซ้ำจำนวนมาก

### Credit risk dashboard

ใช้ `creditLimit`, `currentCredit`, ใบวางบิลค้าง และประวัติการจ่าย เพื่อจัดกลุ่มลูกค้าที่ควรเตือนก่อนขายเงินเชื่อ

ผลที่ควรได้คือพนักงานเห็นสถานะลูกค้าตอนเลือกเงินเชื่อ และแอดมินเห็นลูกค้าที่ควรตามเงินก่อนรอบวางบิลถัดไป

### Watchara rollout finish

ปิดงาน Watchara shared dispenser ด้วยการ validate ตัวเลขกับทีม, ตั้ง env production/staging, deploy, และ backfill/recalculate reconciliation เก่าที่บันทึกก่อน patch

brain ระบุว่าระบบ import และ merge หลักทำแล้ว แต่ยังต้อง signoff และเปิดใช้จริงแบบมีหลักฐานตัวเลข

### Print and device health

เพิ่มหน้าตรวจเครื่องพิมพ์/อุปกรณ์ต่อสถานี เช่น พิมพ์ทดสอบ 58/80mm, ดูครั้งล่าสุดที่พิมพ์สำเร็จ, และแสดง fallback link เมื่อเครื่องพิมพ์มีปัญหา

ระบบมีงาน print สำคัญหลายจุดแล้ว การรู้สถานะเครื่องก่อนปิดกะจะลดปัญหาหน้างานได้มาก

### OCR for meter photos and slips

ทดลองให้ระบบอ่านตัวเลขจากรูปมิเตอร์และยอดเงินจากสลิป เพื่อกรอกค่าเริ่มต้นให้พนักงานหรือแอดมินตรวจ

ควรเริ่มจากโหมดช่วยแนะนำก่อน ไม่ควรเขียนทับค่าจริงอัตโนมัติจนกว่าจะเทียบความแม่นยำกับข้อมูลจริงได้

### Staff UX cleanup

ลดการใช้ `alert()` ในหน้า staff แล้วเปลี่ยนเป็นข้อความใกล้ช่องที่ต้องแก้หรือ toast ที่อ่านง่ายบนมือถือ

จุดนี้ช่วยงานหน้าร้านโดยตรง เพราะ flow พนักงานมี validation หลายจุด เช่น สลิป รูปมิเตอร์ ลูกค้าเงินเชื่อ และเลขบิล
